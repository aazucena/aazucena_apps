# Engineering Standards

To maintain visual integrity across the monorepo, all icon implementations must adhere to the following technical and ergonomic standards.

---

## 🏗️ Visual Weight Balancing

When mixing libraries, developers must be aware of the difference between **Stroke** (MynaUI) and **Fill** (SimpleIcons). Strokes generally feel lighter than solid fills of the same size.

## 🏗️ Accessible Integration

Icons must always be treated as part of the accessibility tree.

| Context | Protocol | Implementation |
|---|---|---|
| **Decorative** | Hidden | Use `aria-hidden="true"` to prevent screen reader noise. |
| **Actionable** | Labeled | Icon-only buttons **must** have a `title` or `aria-label`. |
| **Status** | Described | Icons used as status indicators must include a text fallback for screen readers. |

## 🏗️ CMS Integration (The SVG Protocol)

The registry supports direct injection of raw SVG strings. This allows the CMS to deliver one-off custom icons without package redeployment.

```tsx
// 1. Data comes from Strapi as a string:
const cmsIcon = "<svg ...>...</svg>";

// 2. The registry resolves it:
const ResolvedIcon = getIconComponent(cmsIcon);

// 3. Render it directly (if string):
if (typeof ResolvedIcon === 'string') {
  return <div dangerouslySetInnerHTML={{ __html: ResolvedIcon }} />;
}
```
