# Forms System

The **`@aazucena/forms`** package is a fully type-safe, schema-driven form library for the portfolio monorepo.
It pairs **TanStack Form v1** with **Zod 4** validation and ships **94 pre-composed template components** across 13
domains, from sign-in to incident post-mortems, in three design variants.

---

## Special Components

Beyond templates, the package exports building-block components that templates are composed from:

| Component | Purpose |
|---|---|
| `FormWizard` | Multi-step wizard with Easter-egg challenge on the final step (`showChallenge`) |
| `FormConditional` | Framer Motion-animated conditional reveal — subscribes to form state |
| `FormErrorSummary` | Aggregates all field errors into a dismissible summary banner |
| `FormButton` | Submit button that auto-disables during submission, shows spinner |
| `FormDebugger` | Dev-only panel showing live field state, errors, and dirty map |
| `ControlledInput` | `form.Field` wrapper for `<Input>` with label + validation wiring |
| `ControlledTextarea` | Same as above for `<Textarea>` |
| `ControlledCheckbox` | Same for `<Checkbox>` |
| `ControlledSwitch` | Same for `<Switch>` |

### Multi-step forms with `FormWizard`

```tsx
import { FormWizard } from '@aazucena/forms';

const steps = [
  { id: 'identity', title: 'Identity', component: <IdentityStep /> },
  { id: 'details',  title: 'Details',  component: <DetailsStep />  },
];

<FormWizard
  steps={steps}
  onComplete={async () => { await form.handleSubmit(); }}
  showChallenge={true}   // adds the Easter-egg engagement step before submit
/>
```

### Conditional fields with `FormConditional`

```tsx
import { FormConditional } from '@aazucena/forms';

// Renders with Framer Motion fade/slide when the selector returns true
<FormConditional selector={(state: any) => state.values.role === 'admin'}>
  <ControlledInput name="adminCode" label="Admin Access Code" />
</FormConditional>
```

## Usage Pattern

Every template follows the same contract. Swap the schema and type to use any of the 94 forms:

```tsx
'use client';

import { MFASetupForm } from '@aazucena/forms/templates';
import type { MFASetupFormData } from '@aazucena/forms/schemas';

export function AuthPage() {
  const handleSuccess = (data: MFASetupFormData) => {
    console.log('MFA method selected:', data.method);
  };

  return (
    <MFASetupForm
      variant="glass"
      onSuccess={handleSuccess}
      onError={(err) => console.error(err)}
      defaultValues={{ method: 'authenticatorApp' }}
    />
  );
}
```

## Engineering Notes

### Zod + TanStack Form integration

The `zodValidator` adapter from `@tanstack/zod-form-adapter` is passed via the `validatorAdapter` option.
Due to a TypeScript narrowing issue in TanStack Form's option types, templates use the `as any` cast pattern:

```ts
const form = useForm({
  validatorAdapter: zodValidator(),
  defaultValues: { ... } as MyFormData,
  onSubmit: async ({ value }: { value: any }) => { ... },
} as any);
```

### `.shape` on refined schemas

In Zod 4, `.refine()` and `.superRefine()` keep the `ZodObject` type, so a schema with cross-field checks still exposes `.shape`. Field-level validators can reuse it:

```ts
// registrationSchema checks password === confirmPassword, and .shape still works
validators={{ onChange: registrationSchema.shape.email }}
```

The field validator runs only that field's rules; the cross-field refinement runs on submit.

### `form.Subscribe` selectors

Always type the state parameter as `any` when using `form.Subscribe` directly in templates:

```tsx
<form.Subscribe selector={(state: any) => state.values.method}>
  {(method) => method === 'sms' && <PhoneField />}
</form.Subscribe>
```
