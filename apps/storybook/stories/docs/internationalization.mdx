# Internationalization (i18n)

How content and UI handle more than one locale. Some of this is in place today; the rest is the agreed approach for when a second locale ships.

---

## What exists today

### CMS content (Strapi v5)
Content types have Strapi's i18n enabled, so blog posts, projects and experience entries can carry per-locale fields. English (`en`) is the primary locale.

### Numbers and dates
Format metrics, dates and currencies with the browser's `Intl` API, or the `formatDate` helper in `@aazucena/utils`:

```typescript
new Intl.NumberFormat(locale, { style: 'unit', unit: 'megabyte' }).format(124);
new Intl.DateTimeFormat(locale, { dateStyle: 'medium' }).format(date);
```

### Right-to-left readiness
Components use logical properties (`ms-4`, `ps-2`) instead of `ml-4` and `pl-2`, so layouts mirror correctly. The [Code Style](?path=/docs/docs-code-style--docs) page makes this a rule.

---

## Planned

- **UI strings:** there is no shared string dictionary or localization hook yet. Until there is, keep UI strings in the component that uses them, never in shared constants that mix languages.
- **`lang` attribute:** set `<html lang>` from the active locale once routing supports more than one.

---

## Rules for new components

| Area | Rule |
|---|---|
| Text length | German runs about 30% longer than English. Check components at narrow widths with the Storybook viewport toolbar. |
| Case | Store labels in normal case and transform for display (see [Writing](?path=/docs/docs-writing--docs#capitalization)). |
| Direction | In copy, say "previous", "next", "start" and "end", not "left" and "right". |
| Dates and money | Always `Intl`; never concatenate symbols or month names by hand. |
