# Contributions Guideline

How to work in the **@aazucena** monorepo: setup, structure, standards and the release workflow.

---

## Prerequisites

- **Package manager:** [pnpm](https://pnpm.io/) 10.33.4, the version pinned in `packageManager`. Never npm or yarn.
- **Node.js:** 22.23.4 or later.
- **Git Hooks:** Initialized automatically via [Husky](https://typicode.github.io/husky/).

---

## Getting started

1.  **Clone the repository** and navigate to the project root.
2.  **Install dependencies:**
    ```bash
    pnpm install
    ```
3.  **Start development mode:**
    ```bash
    # Start all workspaces
    pnpm dev
    
    # Start specific workspace
    pnpm web:dev          # portfolio
    pnpm storybook:dev    # this Storybook
    ```

---

## Repository structure

We use a **pnpm + Turborepo** monorepo architecture:

- `apps/`: Main entry points.
    - `portfolio/`: Astro-based primary site.
    - `analytics/`: Engineering Intelligence Terminal (Next.js).
    - `cms/`: Strapi v5 backend.
    - `storybook/`: Documentation and component playground.
- `packages/`: Specialized internal packages.
    - `design-system/`: Design tokens, themes (17 vibes), and platform integrations.
    - `ui/`: 260 shared React components (shadcn base + custom).
    - `visualizations/`: 21 D3-powered chart & graph components with companion hooks.
    - `animations/`: 64+ Three.js objects, GSAP presets, and modular 3D inspection tools.
    - `hooks/`: Domain-specific React hooks.
    - `icons/`: Custom SVG icon library with registry.
    - `utils/`: Pure utility functions (`cn()`, export helpers).
    - `types/`: Centralized TypeScript type definitions.
    - `constants/`: Global constants and fallback data.
    - `context/`: Shared React contexts (Telemetry, etc.).
    - `analytics/`: Tracking and telemetry utilities.
    - `config/`: Shared build configurations (ESLint, Prettier, TS).

## Component development

UI components reside in `packages/ui`, data visualizations in `packages/visualizations`.

- **Styling:** Use [Tailwind CSS 4](https://tailwindcss.com/) with design tokens.
- **UI Primitives:** Prefer [Radix UI](https://www.radix-ui.com/) or [ShadCN](https://ui.shadcn.com/) as base components.
- **Visualizations:** D3-powered charts live in `packages/visualizations/src/d3/` with companion hooks in `src/hooks/`.
- **3D & Animations:**
    - 3D Objects reside in `packages/animations/src/three/objects/`.
    - **Modeling:** Use low-poly/primitive-based geometry for performance.
    - **Fidelity:** Implement **Inverse Kinematics (IK)** for realistic limb motion and follow strict **Canon Landmarks** for pop-culture references.
    - **Registry:** Every new object must be registered in `packages/animations/src/three/objects/registry.ts` with an assigned `cost` tier and `layer`.
    - **Verification:** Use the `ObjectViewer` story to audit $360^\circ$ rotation, materials, and slow-motion mechanics.
- **Animations:** Use GSAP for imperative animations and Framer Motion for declarative ones.
- **Storybook:** every new component needs a `.stories.tsx` file: UI components in `stories/components/`, charts in `stories/charts/`. Follow the [Instrument Language](?path=/docs/docs-instrument-language--docs) and [Code Style](?path=/docs/docs-code-style--docs) pages.
- **Performance:** Heavy dependencies (Three.js, PixiJS, D3) must be lazy-loaded using `React.lazy()` and `Suspense`.

## Coding standards

### TypeScript
- **Strict Mode:** Enabled across all workspaces. Avoid `any` at all costs.
- **Shared Types:** Export common types from `@aazucena/types`.

### Quality Control
- **Linting & Formatting:** Automatically enforced on pre-commit via Husky and `lint-staged`.
- **Manual Check:**
    ```bash
    pnpm lint && pnpm format
    ```

### Commits
- Conventional commits, checked by commitlint: an emoji, a type, an optional scope and a lowercase subject, e.g. `🐛 fix(ui): select items use the control radius`.
- One commit per concern, staging paths explicitly (`git add <path>`), so unrelated changes don't ride along.
- No AI attribution: no `Co-Authored-By` trailers for AI models and no "generated with" lines.

### Changesets
A change to a package that Storybook documents needs a changeset: run `pnpm changeset`, pick the packages and the bump, and write a one-line summary. The [Changelog](?path=/docs/docs-changelog--docs) page renders the result.

## Workflow

1.  **Branch:** work happens on the current phase branch (for example `phase-5/next-release`), merged into `main` by pull request.
2.  **Develop:** implement the change, add tests and stories.
3.  **Verify:**
    - Type-check the touched workspaces, e.g. `pnpm --filter @aazucena/ui type-check`. Full builds run out of memory on the dev machine; Vercel previews are the build check.
    - `pnpm --filter @aazucena/storybook test:ci` for stories and interaction tests.
    - Visual regressions: Argos screenshots every story on `main` in CI; review the diff after merge.
4.  **Pull request:** open it against `main` and wait for CI.

## Performance targets (Phase 3)

We strictly adhere to the performance targets established in Phase 3:
- Initial bundle size target: **< 150 KB gzipped**.
- Use **demand-based rendering** for 3D scenes.
- Minimize top-level static imports in the portfolio entry point.
